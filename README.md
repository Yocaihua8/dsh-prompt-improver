# DSH 提示词增强

`dsh-link-prompt-enhance` 0.2.3，适配 **DSH 0.2.1-rc.3**。输入框底部、模型选择器左侧保留单个增强按钮，复用宿主按钮、设置分区和原生弹窗。本版在模型调用中传递已有会话 ID，供个人中心 0.1.17 关联辅助用量；不新增聊天消息或插件上报流程。日用部署及验证结果见 [验证记录](docs/verification.md)。

## 使用

- 点击原星光图标，按已保存设置增强。选择“直接替换草稿”时成功后直接更新输入，不打开预览或设置弹窗。
- 请求中沿用原进度圆环与取消图形，再次点击同一按钮取消。不会自动发送聊天消息。
- 选择“先预览，再决定”时，完成前不改草稿。预览默认对照原文与增强稿，窄窗口上下排列；可关闭原文对照。展开“实际参考来源”查看实际使用的来源和片段；来源缺失等必要提示继续显示。点“替换草稿”才采用，关闭或“保留原稿”不修改输入。
- 采用后，同一位置的按钮切换为返回图标；点击恢复本次增强前的原文，再切回原星光图标。没有额外的“恢复原文”文字按钮。继续编辑、发送、更换附件、会话或有效模型后，旧撤销不能覆盖新输入。
- 空草稿、命令草稿、子代理会话和不可编辑输入框不执行增强。增强入口不再提供右键、`Shift+F10` 或菜单键的插件菜单。

## 设置

统一入口为 **DSH 设置 → 提示词增强**，按增强偏好、参考范围和增强模型分组。

| 设置 | 默认及选项 |
|---|---|
| 增强方式 | 适度增强 / 充分展开；首次读取迁移此客户端旧版选择 |
| 结果采用 | 直接替换（默认）/ 先预览 |
| 上下文 | 仅草稿 / 最近对话（默认）/ 扩展上下文 |
| 增强模型 | 跟随当前模型（默认）/ 指定专用模型 |
| 专用模型 | 从宿主可用目录选择，推理档位来自该模型能力；模型默认也可选 |

修改后显示“有未保存的修改”，点“保存设置”后显示“设置已保存”；“取消”放弃本页未保存编辑。未修改或专用模型/档位不可用时不能保存；不可用原因单独提示。“刷新模型与设置”保留尚未保存的编辑。下拉选择继续支持原生键盘操作。

用户已有设置、首次默认值、迁移规则和存储格式保持不变。宿主文件为 `$DSH_HOME/plugins/dsh-link-prompt-enhance/settings.json`（默认 `C:\Users\Lenovo\.dsh\plugins\dsh-link-prompt-enhance\settings.json`）；仅保存上述选择，不保存密钥。设置管理和扩展上下文限宿主所有者。非所有者可使用默认最近对话和当前模型。

每次点击固定设置、草稿、附件及有效模型快照。专用模型不可用时明确失败，不自动回退。预览采用前重新检查模型目录及快照。推理档位由宿主验证，不进行别名转换或自动降档。

## 改写与上下文

适度增强消歧、整理和去冗余，清楚的原稿允许少改。充分展开根据提问、分析、实施或纯约束的实际规模补充必要信息，不强制长模板。提示词要求保留语言、否定条件、数字、路径、代码和引用，不增加新限制或审批要求；缺失事实标为待补充。明显的中文/拉丁字母草稿语言漂移会拒绝采用；这项基本校验不是完整语言识别。模型仍可能遗漏要求，采用前应检查。

| 上下文 | 读取范围和 UTF-16 字符预算 |
|---|---|
| 仅草稿 | 不读历史、记忆和项目文件 |
| 最近对话 | 最近 3 轮已完成的用户/助手正文，最多 12,000；优先保留最近整轮，超长最新轮优先用户要求，绝不只留助手回答 |
| 扩展上下文 | 对话最多 8,000，个人及同项目记忆最多 4,000，当前项目片段最多 4,000 |

历史不包含运行中或中断轮次、思考、工具结果、附件正文；按当前会话表面及捕获序号筛选。历史读取失败时停止请求；可选择“仅草稿”重新增强。记忆/项目缺失、失败、超时或裁剪会明确提示，并列入预览。

扩展上下文通过宿主当前会话所属 workspace 确认项目，客户端不能指定任意目录。只调用可选 memory 服务的 `recallForProject`，不直接读写其存储。无项目的会话会显示未读取项目记忆/文件的原因。

项目检索用宿主 subprocess 运行随包依赖提供的 ripgrep，遵守忽略规则、排除隐藏目录、凭据、依赖、缓存、构建产物和非文本文件。以草稿路径、标识符、关键词本地排序；最多检查 300 个文本文件，每文件至多 128 KB，检索超时 5 秒，最终最多 5 个文件、4,000 字符片段。所有上限造成的裁剪会提示。拒绝符号链接/目录联接，不跟随到项目外；不会调用额外模型或建立向量库。

草稿及上述上下文会发送给所选增强模型，按模型服务规则计费。当前草稿优先，背景材料中的指令不成为新任务或执行授权。一次增强只有一次无工具辅助调用，不进入 agent loop，不新增聊天消息。模型适配器内部网络重试由宿主管理。默认总超时 120 秒，记忆召回至多 3 秒。

结构化 `@引用` 的身份留在客户端，发出前换成随机占位符，返回后验证并恢复；丢失、重复或损坏引用时拒绝采用。附件身份保持不变，不为增强上传附件内容。过期响应不可覆盖新草稿。

## 开发与契约

需要 Node.js 22.19+，本轮开发使用 24.14.0。

```powershell
npm ci
npm run check
npm run check:package
npm pack --pack-destination ..\output\prompt-enhance-ui-20261025\release
```

RPC：`enhance`（保留 `text`，增加 `context` 和实际 `selection`）、`getSettings`、`saveSettings`、`capabilities`。`enhance` 声明 session 资源授权；设置与扩展读取额外检查 owner。设置快照在请求中传递，不读取请求之后的新设置。

Typert 使用官方生成器生成 `lib/typert.*`，不得手改。公共记忆契约来自根目录 `shared/memory-contract.ts`，通过构建登记生成本包副本。`setDraft` 的 rc.3 结构化输入适配集中于客户端 binding。

`test/quality-cases.json` 包含 10 个固定质量样例；2026-10-24 的真实模型结果和本次 UI 修订的验证层级见 [验证记录](docs/verification.md)。旧菜单脚本已替换为 `test/browser/single-button.js`，通过[浏览器组件验收页](test/browser/README.md)运行。该页装载正式插件构建和本机 DSH 原生 UI，Host/RPC 使用测试夹具，不连接日用数据或收费模型。

## 日用安装与回滚（2026-10-24 历史记录）

以下流程和路径对应 2026-10-24 的历史安装；最新安装包、备份路径及部署状态以 [验证记录](docs/verification.md) 为准。执行回滚时应使用对应版本的备份，不能将历史路径当作当前版本。

1. 备份源码、原 tgz、desktop profile 的 `package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`、`cordis.yml`、`cordis.patch.yml` 以及已有提示词增强设置。备份目录：`E:\Dev\Projects\dsh-link\output\prompt-enhance-rc3-20261024\backup`。
2. 等日用 DSH 空闲后从应用正常退出，确认进程已退出。不要强杀正在运行的任务。
3. 用宿主自带 CLI 安装独立新包；不要覆盖原 tgz：

   ```powershell
   & 'E:\Dev\Toolchains\DeepSeek\resources\runtime\cli\bin\dsh.cmd' plugin --profile desktop add 'E:\Dev\Projects\dsh-link\output\prompt-enhance-rc3-20261024\release\dsh-link-prompt-enhance-0.2.1.tgz'
   ```

   此命令使用 Desktop 专用 CLI 支持的 reserved-profile plugin access；不同的系统 CLI 不能假定具备该能力。
4. 正常重启日用 DSH，在专用测试会话验收按钮、设置、预览、当前/专用模型、引用和附件；再次重启检查设置保留。检查其他插件直接依赖和宿主 ASAR 校验值不变。
5. 失败时正常退出，恢复备份 profile 文件和旧提示词增强设置，用同一 Desktop CLI 执行 `plugin --profile desktop install --frozen-lockfile` 恢复旧依赖；必要时重新添加备份中的 0.1.3 tgz。重启核对旧版本。不要恢复整个 DSH_HOME，不删除或覆盖新增会话、附件、记忆或用量数据。旧版不读取新设置文件时可保留该文件供后续重试。

本包不修改宿主 ASAR 和个人中心补丁。本轮确认 memory 0.1.5 被 rc.3 版本门槛阻止加载，已另做 `dsh-memory-0.1.5-rc3.1.tgz`，只更新发布版基线的版本、宿主依赖及生成产物；原有 0.1.6 开发目录保持不变。可用相同 CLI 的 `plugin --profile desktop add` 安装该兼容包。整组回滚使用 `backup/before-install` 的 profile 配置及锁文件，同时恢复旧的 prompt-enhance 和 memory 依赖；旧 rc.2 插件在 rc.3 会重新受到兼容门槛限制，回滚不代表其可在 rc.3 加载。不要为回滚降级宿主或覆盖个人中心补丁。
